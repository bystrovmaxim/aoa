## Design and implementation work packages

### W1 — Normalize resolved fields and enforce completeness (FR-001–008, FR-015–016)

Use completed `FieldInfo.annotation` plus `FieldInfo.metadata` as the canonical source. Remove dependence on re-evaluating original module annotations with `get_type_hints`; explicitly rebuilt cross-module fields must retain their markers. Do not use first-non-null union selection to accept ambiguous relation shapes. Require exactly one direction marker and existing description/default discipline.

Enumerate all loaded declared entity hosts for completeness, including graph-excluded hosts, while keeping specialization's existing publication enumeration unchanged. Do not validate abstract framework kind bases as user declarations. Exclusion suppresses publication, not declaration checking. Resolve before classification; unresolved/unsupported entity-bearing types fail closed. Reject bare Enum and structural fields, raw containers hiding entities and `NoRelation` alternatives.

Runtime validation enforces normalized semantics. Pydantic discards where `Field` was written; source placement/count is therefore a separate scoped AST check accepting explicit file roots. It must validate aliases and annotation/assignment forms used by the permitted corpus, fail/report unsupported relevant forms rather than silently ignoring them, and never scan prohibited paths. Runtime acceptance must not depend on source availability.

### W2 — Resolve reciprocal inverse declarations (FR-008–010)

Infer field-only inverse targets from normalized container targets. Check an explicit target by identity. Build an index keyed by canonical `(declaring_owner_class_identity, field_name)` endpoints and require reciprocal resolution back to the same endpoint. Track effective_host separately: unchanged inherited fields retain the base declaring owner, but every effective host still receives completeness checks and its own graph projection. Explicit overrides and target-changing generic substitutions create new endpoints. Respect normal effective-field/MRO selection and deduplicate only the same inherited declaration, never unrelated same-named fields. Discover provenance from runtime class/model metadata without requiring source files or re-evaluating raw annotation strings. See the inheritance table in contracts/complete-declarations.md. `NoInverse` remains a valid unpaired declaration and cannot be a claimed reverse endpoint. Extend existing specialization head/alternative handling rather than treating vocabulary parameters as relation fields. Do not create a compatibility/ownership table.

Run local completeness and relevant-endpoint inverse validation for supported direct entity graph projection as well as global coordinator/factory paths. Validation reads descriptors, not graph constructors, preventing recursion on cyclic models. Reuse the validated descriptors when projecting edges. Confirm how injected coordinators represent an already successful build; do not allow a supported injection path to publish an unvalidated graph.

### W3 — Implement dictionary association runtime contract (FR-006, FR-011–013)

Add generic Pydantic integration for `AssociationOne[D]` only when D is a resolved concrete dictionary. Structural generic targets retain their established instance validation and runtime behavior. Python host input requires an explicit wrapper. Resolve its code, verify supplied member identity and create a new frozen wrapper containing the canonical member; do not mutate the caller's wrapper.

JSON container input has the explicit shape specified in [the dictionary contract](contracts/dictionary-association.md). Use JSON/Python schema branches to distinguish transport input from opaque Python instances. JSON serialization delegates to the canonical member's existing JSON reference serializer; Python access keeps the wrapper. Reuse handler-managed dictionary schemas/definitions, including custom property serializers, instead of hand-copying `$defs`.

### W4 — Generate ordinary graph associations and migrate consumers (FR-014)

Use the existing `EntityGraphEdge` path with `relation_type=association`, cardinality one and `has_inverse=false`. Retire new-source special-reference emission. Extend dictionary-target detection for field hints, but do not inadvertently reactivate special-edge discovery through that shared helper.

Adapt `EntityFieldGraphEdge` filtering so the explicit dictionary association retains one field row. Reuse the ordinary relation schema with all its required properties. Keep the legacy edge schema and DuckDB loader table for historical inputs. Maxitor new graph fixtures use the ordinary association SQL path. Merge its retained dictionary field row and ordinary FK metadata by `(entity_id, field_name)`: preserve field_id/type/ordinal/reference_qualname, enrich foreign_key, and suppress the synthesized FK fallback for that exact field rather than relying on full-row DISTINCT. Distinct fields to one dictionary stay distinct; ordinary structural fallback and historical payload behavior remain. Retain isolated legacy-input tests and assert one field row and one arrow per dictionary field, including cross-domain slicing. Inspect renderer tests for existing type-hint/card display assumptions.

### W5 — Migrate authorized corpus and verification fixtures (FR-017–019)

Inventory allowed production declarations, unit/integration fixtures and teaching material only. Migrate required/nullable dictionary selections, relationship values and reciprocal markers together. Keep each stereotype's own positive/refusal cases, including Assoc endpoints, Detail owner/reverse and Spec alternatives. Negative declared-class fixtures must live in isolated subprocesses or scoped fixtures so global loaded-class validation does not poison unrelated graph builds.

Preserve baseline controls for ordinary container hydration, catalogue/property validation, schemas and State/Lifecycle. Baseline current tests are not proof of the new feature: new tests must assert new refusals and canonical identity explicitly.
