## What the migration found that the plan did not

examples/step_22_lifecycle/19_non_json_field.py declares a state field named `value`:

    value: Opaque = Field(description="An opaque Python value")
    DRAFT = value(code="draft", display_name="Draft", value=Opaque())

The annotation binds the name `value` in the class body, so the factory is shadowed and the
declaration fails with `TypeError: 'FieldInfo' object is not callable`. The alias never
collided because it answered the class's own name. The example now calls the field
`payload`, the constraint is written into contracts/declared-value.md §1 and data-model.md,
and the escape hatch is covered by
test_declared_values.py::test_a_field_named_value_needs_the_factory_under_another_name:
a model that needs the field imports the factory as `value as declared`.

## One trap for later phases

`ruff check --fix` rewrites .ipynb files, turning each code cell's source string into a list
and removing imports it finds unused — it dropped a class definition from
examples/step_26_maxitor/01_graph.ipynb. That run was reverted, the migration was re-applied
with the notebook migrator, and examples/ must not be passed to ruff with --fix. The check
run does not include examples/, so this is a local-workflow note, not a gate.
