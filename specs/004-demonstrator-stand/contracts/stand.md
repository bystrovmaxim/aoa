# Contract: the stand deployment

The stand is judged by opening two URLs and by running one command. This file is the contract between the repository (images, compose file, script) and the host (`194.67.66.48`).

## What the deploy command must do, in order

1. **Gates before anything else**
   - both `dev.demo.aoa.run` and `dev.maxitor.aoa.run` resolve — otherwise print the missing record and exit non-zero;
   - the host's existing TLS terminator is detectable — otherwise print "terminator not identified" and exit non-zero.
2. **Build** — `docker compose build` builds both images from this repository (Maxitor including the client build).
3. **Up** — `docker compose up -d` starts both containers on their loopback ports.
4. **Healthcheck** — poll both containers' health endpoints until healthy or timeout.
5. **Verify** — `curl` both `https://` domains; the diagram must render (Maxitor), the service must answer (demo).
6. **Rollback on any failure** — restore the previously running images/containers and report the failure; the stand is never left half-deployed.

## Environment contract

- Configuration and secrets are read from `/etc/aoa-stand.env` on the host; the repository carries only `deploy/stand/.env.example` with the names, never the values.
- SSH access to the host: either existing key (`up2y-prod` / `digtwin-prod`), whichever works.

## Recorded picture manifest

- `stand-use-case.dot` / `stand-use-case.svg` — the use-case diagram, generated by the client's own builder.
- `stand-erd.dot` / `stand-erd.svg` — the ERD slice, generated by the client's own builder.
- `stand-use-case.png` / `stand-erd.png` — browser captures from the stand itself (the look-at evidence).
