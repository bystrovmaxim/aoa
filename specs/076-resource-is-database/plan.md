# Implementation Plan: A resource is a database, and the model knows no store

**Branch**: `feature/issue-487-resource-is-database` | **Date**: 2026-11-07 | **Spec**: [spec.md](spec.md)

`src` = `packages/aoa-action-machine/src/aoa/action_machine`, `tests` = `packages/aoa-action-machine/tests/action_machine`.

## Design

- **The entity names its domain** — `@entity(description, domain=…)` writes `{"description", "domain"}` into `_entity_info`; the `resource=` argument and its checks go. `EntityIntentResolver.resolve_domain_type` reads the entity's own domain; `EntityGraphNode.domain` is built from the entity itself, and the `entity_resource` edge and its check in `NodeGraphCoordinator._validate_entity_resource_edges` are removed. The `@meta` rule changes with it: a resource takes no domain (a database is shared by domains), an action keeps its mandatory domain, and the data-source exception in `_validate_meta_host_domain` goes.
- **The database declares its entities** — a new `@entities(*classes)` decorator in `src/intents/entities/` writes `_entities_info` on a resource class. It refuses a non-resource target and a class that is not `@entity`, accepts every resource kind, keeps the declaration order, and permits an empty list. A new resolver in the same package reads it. Relation checks no longer know a resource: `resource` drops out of `EntityGraphNode`'s field list, out of the relation validators' inputs, and out of the demo's test models.
- **The data source leaves** — `src/resources/base_data_source.py`, `src/resources/data_source_resolver.py`, `src/resources/in_memory/` (`InMemoryDataSource`) and `src/resources/external_service/` (`ExternalServiceDataSource`) are deleted, with `graph/nodes/data_source_graph_node.py`, `graph/edges/resource_data_source_graph_edge.py`, `graph/validators/entity_data_source_validator.py` and the data-source half of `resource_domain_validator.py`. `BaseResource` loses `Generic[TDataSource_co]`, `data_source_type()`, `_check_data_source()`, and the `TDataSource_co` type variable leaves every base (`BaseStorage`, `SqlStorage`, `PostgresStorage`, `SqlStorageWrapper`, the adapters' resources).
- **The pool replaces the data source** — `resources/postgres/postgres_pool.py`: `PostgresPool(dsn, **pool_options)` or `PostgresPool(pool=<ready pool>)` — exactly one — with `open`, `close`, `acquire`, `release` and `async with`, carrying the body of today's `PostgresDataSource` and none of its intent. It has no kind, no `@meta`, no graph node, and no place in the model. `PostgresStorage.__init__(pool=None, *, connection_params=None)` takes exactly one: with a pool it acquires a connection in `open()` and returns it in `close()` (today's body); with connection parameters it opens its own connection per call and closes it. Both or neither is refused with `ConnectionValidationError`. A non-PostgreSQL storage refuses either argument. The three assembly modes — lifespan pool, script connection, test substitute pool — are shown in a demo example and the resources page.
- **The check on return** — two new modules: `src/resources/entities/plan.py` computes, for a resource class, the classes its `@entities` lists and, for each, whether a relation reachable from it leads to a class outside the list; `src/resources/entities/walk.py` walks an answer by that plan. The plan is frozen data kept per concrete class — in `cls.__dict__['_entities_plan']`, never read from a parent — computed when the model is built (`NodeGraphCoordinator.build`) and lazily on first call when a resource is used without a machine. The wrapper always looks it up for `type(self)`, so a subclass with its own `@entities` is checked by its own list. The plan treats dictionary members (`BaseEnumEntity`) and lifecycle states (`BaseStateEntity`) as the model's: they pass wherever they appear, and a relation to a dictionary is not a way out of the list.
- **Where the wrapper sits** — `BaseResource.__init_subclass__` wraps each public function of the declared class body once (a marker attribute keeps it idempotent): a coroutine function is replaced by one that awaits the answer and walks it; a plain function walks its answer; an async generator is checked element by element as it yields. Names starting with `_` are left alone, and so are class methods, static methods and properties (`get_wrapper_class` is a class method since #486); a plain generator and a plain function that returns an awaitable are not checked. This is what makes `connections[…]`, `box.resolve(…)` and a test-bench substitute all checked: they hand over the same object, so its own methods check. It keeps `isinstance` and identity intact — no proxy. The per-kind nesting wrapper from #486 (`SqlStorageWrapper`, `OcelStorageWrapper`, an application's `…StorageWrapper`) still blocks lifecycle methods for a nested action; its own methods are checked by the plan of the resource it wraps, read from the wrapped instance, since a wrapper has no `@entities` of its own. A test-bench substitute is checked when it is a resource instance; a bare `Mock` is not a resource and is not checked.
- **The walk** — `walk_answer(value, plan, resource_name, entry_point, path)` refuses an entity whose exact class the plan does not list, and an entity of an unlisted class loaded into a relation, even a partial one that holds only its id; a relation that leads out of the list passes only unloaded — its container holds the id and no entity. Dictionary members and lifecycle states pass. It descends into a list, tuple and mapping values, names attributes and `[index]`/`[key]` in the path, and raises `ResourceEntitiesError` (a `TypeError`, like every AOA refusal) with the message of the spec: `ShopDatabaseStorage.get_order returned ProductCoreEntity at order.lines[0].product, which @entities(ShopDatabaseStorage) does not list`. A resource without `@entities` refuses every entity the same way. The walk stops at a class the plan marks as needing only its type check, and starts with one `isinstance(..., BaseEntity)` look for answers without entities.
- **The graph at 2.0** — `graph/edges/resource_entity_graph_edge.py` (`resource_entity`, aggregation, from resource to each listed entity); `ResourceGraphNode.get_all_edges` returns no domain edge and no data-source edge, its `@entities` edges instead; `EntityGraphNode` keeps only its own `domain` edge. `graph_json_schema.json` and its docstring move to `packages/open-gnomon-protocol/graph/2.0.json` from gnomon's merge commit of #66 (`5d9dac89617aef08ea508988ce9106c1d82d8285`), and `graph-builder` is taken from that commit. `tests/scripts/test_schema_copies.py` follows the new version.
- **The demo becomes databases** — the store, support and inventory resources over `ShopDataSource` merge into one `ShopDatabaseStorage` listing their entities; every other demo storage keeps one database and gains `@entities`; the data source classes and the `[DataSource]` arguments are deleted; the gateways keep their kind; a gateway that holds entities lists them — `NotificationGateway` lists `RecipientDeviceSeenCoreEntity`, `CardNetworkGateway` lists `PaymentEventLogCoreEntity` — and the others declare no `@entities`. The merged resources live in a new `model/databases/` package, one module per database. The demo's test model and the adapters' test models follow.
- **Removed rules** — `resource_domain_validator` loses both passes (only resources of the action's domain; one resource per domain and data source); `entity_data_source_validator` goes; the coordinator drops the `resource_data_source` and `entity_resource` checks and gains the `resource_entity` one. The docs pages that state the old rules are rewritten in T010.
- **Versions** — every package raises: `aoa-action-machine` (API removed), `aoa-demo`, the three adapters (`aoa-fastapi-adapter`, `aoa-mcp-adapter`, `aoa-langgraph`), `aoa-ocel` and `aoa-otel` for their migrated imports. The graph files of the demo are rebuilt at protocol 2.0.

## Verification and documentation

Each phase runs only its test files. For every new refusal and every path of the walk, the check is removed or bypassed on purpose, the matching test must fail and no unrelated test of that phase, then the code is restored and the exact command and output recorded.

T010 documents the model (an entity with a domain, a database with its entities), the check on return (a listed entity, an unlisted one, a reference, an iterator, a resource without `@entities`), the three ways to reach a database, and the migration of every removed name — as paired scripts and notebooks, executed while written. Every refusal is a case. Old identifiers stay only in `specs/`, historical changelogs and labelled migration fragments.

## Constitution Check

One phase = one commit; adversarial verification on each phase's own tests; the tail in order — the closing check run, the documentation, the changelog; every changed level raises its version; nothing is committed, pushed or merged without the maintainer's word. The change removes public API, so the changelog says how to migrate, and the docs pages that state the removed rules move with it. No `type: ignore` is added.
